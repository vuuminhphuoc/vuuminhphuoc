# Project Overview: `vuuminhphuoc/vuuminhphuoc`

This repository serves as the special GitHub Profile README repository for user [`vuuminhphuoc`](https://github.com/vuuminhphuoc).
Its primary role is to dynamically generate and display personalized stats (lines of code, commits, stars, account age) in SVG badges for both light and dark mode on the GitHub profile page.

> **Ecosystem Context:** This repository is linked to `my-portfolio` (canonical hub), `career-ops` (job search), and `openshorts` (video showcase). For full cross-repo architecture, data flows, and team guidelines, read [`HANDOFF.md`](./HANDOFF.md).

---

## Repository Structure

- `README.md`: Minimal HTML/markdown rendering `<picture>` pointing to `dark_mode.svg` and `light_mode.svg`. Generated by `render_profile.py`; the outer `<a>` links to the public portfolio.
- `today.py`: Core Python script responsible for fetching GitHub account data, GraphQL statistics, lines of code, commit counts, and dynamically rewriting SVG graphics (`light_mode.svg` & `dark_mode.svg`).
- `render_profile.py`: Offline, stdlib-only renderer that injects the curated public profile (role, contact, capabilities, work history) into the profile column of both SVGs and regenerates `README.md`. Reads `profile.json` (or `--profile <path>`), never touches the network or the GitHub stats ids owned by `today.py`.
- `profile.json`: Sanitized snapshot of the canonical workspace profile, produced by the shared sync script in `my-portfolio`. Not hand-edited here.
- `light_mode.svg` / `dark_mode.svg`: Generated SVG templates showing live stats.
- `cache/`: Contains cached response hashes and `requirements.txt`.
- `.github/workflows/build.yaml`: GitHub Actions cron workflow running daily (`0 4 * * *`) and on push/dispatch to update profile stats and commit changes back to `main`.

## AI Agent Guidelines & Architecture Rules

### 1. File Modification Safeguards
- **DO NOT** replace `README.md` with standard text/markdown profile layouts unless specifically instructed by the owner. It must remain a clean image/SVG container for GitHub profile rendering.
- **DO NOT** hardcode secrets or personal access tokens into `today.py`. All GitHub GraphQL / REST requests must consume `ACCESS_TOKEN` and `USER_NAME` via environment variables.
- **DO NOT** rename or remove the statistical ids in the SVGs (`age_data`, `repo_data`, `contrib_data`, `star_data`, `commit_data`, `follower_data`, `loc_data`, `loc_add`, `loc_del`, plus their `*_dots` partners); `today.py` locates its rows through them. The ASCII portrait column (every `<tspan>` at `x="15"`) and the `<style>` block are equally load-bearing.
- **DO NOT** edit `README.md` or the profile column of the SVGs by hand: `render_profile.py` regenerates them from `profile.json`. Edit the canonical profile in `my-portfolio/data/profile.json` instead.

### 2. Runtime & Dependencies
- Python version: `>= 3.11`
- Dependencies (`cache/requirements.txt`):
  - `python-dateutil`
  - `requests`
  - `lxml`

### 3. Workflow Invariants (`.github/workflows/build.yaml`)
- The GitHub Actions workflow executes on `ubuntu-latest`.
- Actions required permissions: `contents: write`.
- `render_profile.py` MUST run after `today.py` in the same job: `today.py` refreshes the live statistics, then the renderer reapplies the curated profile without disturbing them.
- The renderer is offline (stdlib only) and takes no token, so it cannot fail because of GitHub API limits or missing secrets.
- If Git commit/push fails in GitHub Actions with `fatal error in commit_refs`, it is typically a transient GitHub remote ref lock / network hiccup — trigger a manual re-run with `gh workflow run build.yaml --repo vuuminhphuoc/vuuminhphuoc`.

### 4. Local Execution & Testing
To test `today.py` locally:
```bash
python -m pip install -r cache/requirements.txt
# Set environment variables:
export ACCESS_TOKEN="<your_github_pat>"
export USER_NAME="vuuminhphuoc"
python today.py
```
*(On Windows PowerShell: `$env:ACCESS_TOKEN="..."; $env:USER_NAME="vuuminhphuoc"; python today.py`)*

### 5. Profile Rendering

`render_profile.py` needs no third-party packages and never calls the GitHub API:

```bash
# Uses ./profile.json (the snapshot synced from my-portfolio/data/profile.json)
python render_profile.py
# Or render straight from the canonical workspace profile
python render_profile.py --profile ../my-portfolio/data/profile.json
```

It rewrites `light_mode.svg`, `dark_mode.svg` and `README.md` in place and is deterministic and idempotent — rerunning it produces identical bytes.
